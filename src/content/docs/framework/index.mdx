## Three layers and a loop

| Layer | Who | What happens there |
| --- | --- | --- |
| **Factory HQ** | People | Intent, creativity, steering and judgment. Dev tools, ideation, collaboration, planning, controls and observability. Always bright. |
| **Factory floor** | Agents | The heavy lifting. Models, agents, delivery and production environments, automations and security. This is where the lights dim. |
| **Factory foundations** | Shared platform | What the factory is built on: code artifacts, tools, context, and identity and access. Stronger every loop. |
| **Engineering** | Platform engineers, a partner or both | Builds the factory itself: tunes trust and control, expands automation and strengthens the foundations. |

The layers connect in four directions:

- **Down from the HQ:** intent, steering and approvals.
- **Up from the floor:** evidence, signals and cost.
- **Into the foundations:** specs, skills, learnings and attestations, versioned in Git.
- **Around all of it:** the [engineering loop](/framework/engineering/) that builds and tunes the factory.

## One line, four stations

Work flows across the floor through the same four stations at every level. The HQ sends intent down and gets evidence back; the foundations supply context and keep what the line learns.

## Built on GitHub, better with Microsoft, open by design

The framework is opinionated about **capabilities**, not about vendors. GitHub is the default factory floor; Microsoft adds business context, agent identities, evals and a cloud that runs and learns from what ships. Every component also lists the third-party tools teams already use, connected through open standards like MCP and Agent Skills. You can see all of them in the [big picture](/#what).
