## Is this a product?

No. The Bright Factory Framework is an opinionated framework: a blueprint, levels, playbooks and principles. You build the factory with products you choose, GitHub and Microsoft by default and the tools you already use where they fit.

## Do we need to use only GitHub and Microsoft?

No. The framework is composable by design. Each component lists defaults and alternatives, and open standards like MCP and Agent Skills connect the tools you already have. See the [big picture](/#what).

## Does lights-off mean nobody is watching?

Never. The floor can go dark, the HQ never does. Every session, tool call, decision and cost is traced, and people set the guardrails and decide the exceptions. See [bright vs dark](/fundamentals/bright-vs-dark/).

## What level should we start at?

Most teams start at Crawl and move one work type at a time. [Take the self-assessment](/get-started/find-your-level/) to see where you are today.

## Can different teams be at different levels?

Yes, and they should be. Levels are set per work type, so dependency upgrades might run lights-off while a regulated flow stays at Crawl.

## What happens when autonomy goes wrong?

You dim back up. Approvals return to people for that work type, automations pause and work continues from Git. It takes minutes, and you should rehearse it. See [dim back up](/levels/dim-back-up/).

## What does multiplayer mean?

Agent sessions that more than one person can see and steer. Singleplayer is one developer with agents on a laptop; multiplayer moves sessions to the cloud for the team; multiplayer at scale runs fleets across the organisation. See [singleplayer to multiplayer](/framework/multiplayer/).

## Who builds the factory?

A platform engineering team, a partner, or both. Building the factory is a lit job that never goes dark. See [engineering the factory](/framework/engineering/).

## Can partners build on the framework?

Yes. Partners can package their own IP on the framework, such as assessments, skills, agents, accelerators and managed operations. See [for partners](/get-started/partners/).

## Some products are marked new or preview. Can we use them?

Products marked **new** are recent or in preview. Preview features may change before general availability, so check each product's documentation and your agreements before using them in production.

## Are the playbooks finished?

Not yet. The playbooks are drafts: the steps and exit criteria are set, and detailed UI and CLI instructions are coming.

## Can agents read these docs?

Yes. Every page is available as Markdown: use **Copy page** or **View as Markdown** at the top of any page. The whole site is indexed in [`AGENTS.md`](/AGENTS.md), and the full text is in [`llms-full.txt`](/llms-full.txt).
