## The four steps

Every factory in this framework is built the same way: one team, one work type, one level at a time.

<JourneySteps />

## Your first hour

In your first hour, start the first three steps. Scale comes later, work type by work type.

- **Explore: read the fundamentals.** Fifteen minutes on [what a software factory is](/fundamentals/) and why this one is [bright, not dark](/fundamentals/bright-vs-dark/).
- **Assess: pick one work type.** Dependency upgrades, bug fixes, test coverage or a small feature area. Something frequent, low-risk and easy to measure.
- **Assess: find its level.** Answer the [self-assessment](/get-started/find-your-level/) for that work type. Your result is saved in this browser and every page follows it.
- **Assess: read your level.** See who does what at each station, which primitives you need and what evidence lets you move up: [Low autonomy](/levels/low/), [Medium autonomy](/levels/medium/) or [High autonomy](/levels/high/).
- **Pilot: open the playbook.** Step-by-step instructions for your level, with a UI track and a CLI track. Then [rehearse dimming back up](/levels/dim-back-up/) before you go further.

## What you need

- **A GitHub organisation with GitHub Copilot.** Everything starts here: repositories, pull requests, Actions and Copilot in the IDE, the CLI and the Copilot app.
- **Your existing tools.** The framework is composable. Keep the tracker, chat, CI and cloud you already use where they fit, and connect them through open standards like MCP.
- **Optional, and better with Microsoft.** Azure, Microsoft Foundry, Microsoft Entra and Microsoft 365 add business context, agent identities, evals and a cloud that runs and learns from what ships.

Some capabilities in the framework are in preview or need a specific plan. The [product catalogue](/reference/products/) links every product to its official page so you can check availability.
</Aside>
