**Time:** A few days for one work type, after low autonomy.

## Before you start

- The low autonomy playbook done for the repositories in scope.
- Copilot cloud agent enabled for the organisation and repositories.
- A named owner for each agent and each work type.
- An Azure subscription if you plan to use Azure SRE Agent or Foundry.

## Steps

*Coming soon:* detailed UI and CLI instructions for each step.

1. **Give agents identities.** Every agent acts under its own identity, with least privilege and an accountable owner.
2. **Hand work to Copilot cloud agent.** Assign well-specified issues to Copilot cloud agent and let it build in a cloud sandbox.
3. **Configure the agent environment.** Give the cloud agent the tools, MCP servers, secrets and firewall rules it needs, and nothing more.
4. **Start work from events.** Add automations that start agent work from issues, schedules and signals.
5. **Steer from mission control.** Watch, steer and continue sessions as a team, from any device.
6. **Connect production signals.** Route incidents and alerts from production into new, well-described issues.
7. **Approve by risk, within budget.** Decide which changes need which approvers, and set budgets per agent and per team.

## Evidence to move up

- Agents finish most assigned tasks with mergeable pull requests.
- Every agent has an identity, a budget and an owner, and audit logs prove it.
- Low-risk changes merge on evidence, without waiting for a full review.
- The team has rehearsed dimming this work type back up.

When the evidence holds, move this work type to [high autonomy](/levels/high/) and open the [high autonomy playbook](/playbooks/high/).

## If you need to dim back up

Return approvals for this work type to people and pause its automations. Work continues from Git. [How to dim back up →](/levels/dim-back-up/)
