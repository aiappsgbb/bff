**Time:** Weeks, one work type at a time, after medium autonomy.

## Before you start

- The medium autonomy playbook done for the work types in scope, with stable SLOs.
- An agent registry and an owner for each fleet.
- End-to-end test environments that agents can create and tear down.
- A rehearsed switch to dim back up for every work type in scope.

## Steps

*Coming soon:* detailed UI and CLI instructions for each step.

1. **Write policy as code.** Turn guardrails, approvals and budgets into versioned, reviewed policy that applies to every agent.
2. **Register and govern agents.** Register every agent, its owner, permissions and evals in one place.
3. **Run fleets per work type.** Give each work type its own fleet, sandbox and firewall rules.
4. **Prove every change end to end.** Every pull request carries an evidence bundle: tests, scans, evals, previews and cost.
5. **Evaluate the agents.** Run evaluations for every agent and block releases on regressions.
6. **Release progressively.** Ship behind flags, in rings, with automatic rollback on SLO breaches.
7. **Approve by exception.** People approve only what policy flags. Everything else merges and ships on evidence.
8. **Rehearse dimming back up.** Pull the switch for one work type, keep the business running, then move back down on evidence.

## Evidence to move up

- SLOs hold for lights-off work types, release after release.
- Every change has an evidence bundle and a full trace.
- Dimming back up has been rehearsed and takes minutes.

High autonomy is not the end. Keep tuning trust, automation and foundations with the [engineering loop](/framework/engineering/), and move the next work type.

## If you need to dim back up

Return approvals for this work type to people and pause its automations. Work continues from Git. [How to dim back up →](/levels/dim-back-up/)
