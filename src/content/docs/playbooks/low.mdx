**Time:** About half a day for one repository.

## Before you start

- A GitHub repository you can administer, with a test suite that runs.
- GitHub Copilot Business or Enterprise, with the policies your organisation needs enabled.
- GitHub Advanced Security, or the security tools you already use, connected to the repository.
- The Copilot app, the Copilot CLI or an IDE with Copilot, on your laptop.

## Steps

*Coming soon:* detailed UI and CLI instructions for each step.

1. **Protect the main branch.** Turn on a ruleset for the default branch: pull requests required, status checks required, and code owners for the paths that matter.
2. **Make CI the first gate.** Every pull request runs build, tests and scans before anyone reviews it.
3. **Write down your context.** Add repository custom instructions, an `AGENTS.md` and a first agent skill, and review them like code.
4. **Start from an issue.** Pick a small, well-scoped change and capture the intent in an issue.
5. **Turn the issue into a spec.** Plan with Copilot: acceptance criteria, approach and test plan, saved in the repository.
6. **Build with Copilot.** Let Copilot implement the spec while you watch, steer and accept each edit.
7. **Review with evidence.** Open the pull request. Copilot code review, CI and security scans produce evidence; a person approves.
8. **Merge and observe.** Merge, release as usual and watch the signals. Note what to improve in your instructions and skills.

## Evidence to move up

- Required checks run on every pull request, and the team trusts what they report.
- Instructions and skills exist, are reviewed and improve every week.
- Most agent-assisted pull requests merge with few corrections.

When the evidence holds, move this work type to [medium autonomy](/levels/medium/) and open the [medium autonomy playbook](/playbooks/medium/).

## If you need to dim back up

Return approvals for this work type to people and pause its automations. Work continues from Git. [How to dim back up →](/levels/dim-back-up/)
